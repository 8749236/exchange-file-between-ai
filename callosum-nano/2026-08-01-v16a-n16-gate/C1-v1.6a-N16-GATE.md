# C1-v1.6a：N16 双种子桥接门控（冻结）

日期：2026-08-01（America/Toronto）

## 目的

在启动 BASE/MATCH 20k 长跑前，先验证 Callosum Nano 自身 harness 是否能在
N=16、充足 4k 窗口内稳定跨过绑定/组合相变。ref2 已证明数据任务可学，但它与
Callosum MATCH 仍同时存在模型和训练目标差异，不能直接充当 20k 计时器。

本炉只跑 `oracle-left`，不解冻 C1-A/B/C，也不续训 v1.5。

## H 格：真实 harness

- exact `chain-two-hop`，N=16，random filler
- 2 layers / width 64 / 2 heads / learned position
- AdamW，lr=3e-3，weight decay=0，clip=1
- batch=32，warmup=100，constant LR
- `full_lm_lambda=1`
- seeds 1,2；4000 steps；固定验证生成语义，1024 episodes

H 保留 v1.5 MATCH 的实际训练配置，只把 ID 数降为 16，并给 ref2 相变点约 2×
步数余量。

## M 格：ref2 训练镜像（仅在 H 未双 seed 通过时运行）

模型仍是 Callosum Nano，但把可对齐的训练差异改为：

- batch=64
- warmup=1
- `full_lm_lambda=0`

其余与 H 相同。M 不能消除 pre-RMS、自定义 adapter、独立 64 类 heads 等模型
差异；它只判断损失/batch/warmup 训练 bundle 是否足以解释 H 的失败。

## 预注册门与判读

每个 seed 均按 step-4000 **endpoint** 判定，同时要求：

- `free_code_acc >= 0.90`
- `free_v_given4_acc >= 0.90`
- `free_chain_exact_acc >= 0.90`

| H | M | 判读与下一步 |
|---|---|---|
| 双 seed 通过 | 不运行 | Callosum harness 阳性；再冻结 N64 长窗，不直接归因 BASE |
| 未通过 | 双 seed 通过 | 训练 bundle 是关键；先拆 full-LM/batch/warmup，不跑 BASE 20k |
| 未通过 | 未通过 | 仍有模型实现差异；20k 对现有 BASE/MATCH 缺乏阳性标尺 |

单 seed 通过、单 seed 失败统一归入“未双 seed 通过”，不挑 seed，也不把 best
checkpoint 代替 endpoint。轨迹形状保留作诊断，不进入成功门。

## ref2 原始轨迹的边界修订

N16 seed-2 并非“全程平台至 1800”：其 `tf_v` 在 step 1000 已为 0.9668，
step 1200 起约 1.0，而 `free_c` 直到 step 2000 才跃迁。故可保留“存在阶跃和
多阶段动力学”，但不能宣称固定的“绑定腿总先于组合腿”；阶段顺序至少会随 seed
改变。
