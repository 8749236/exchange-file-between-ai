# C1-v1.5：模型侧结构诊断（预注册）

## 目的与边界

v1.4 已排除“仅把 LR 提高 10 倍”与“仅移除 full-LM”足以使 Oracle 逃逸。
v1.5 只校准 Oracle，定位模型侧差异；不运行 A/B/C，不产生任何胼胝体结论。

## 固定项

除下表明确改变的项目外，全部固定为：

- `oracle-left`，seed 1，64 IDs，random filler，chain-two-hop；
- batch 32，2000 steps，warmup 100，constant LR；
- full-LM λ=1.0，grad clip 1.0；
- fixed validation 1024，eval interval 200；
- interface width 64，MLP ratio 4，dropout 0；
- step-2000 endpoint 判读，不挑 best；
- 所有格 fresh run，测试通过后开炉。

## 五格设计

| cell | layers | width / heads | position | weight decay | LR | 角色 |
| --- | ---: | --- | --- | ---: | ---: | --- |
| BASE | 4 | 48 / 3 | RoPE | 0.1 | 3e-4 | v1.4-L1 新鲜复现 |
| WD0 | 4 | 48 / 3 | RoPE | 0.0 | 3e-4 | weight decay 单因素 |
| W64H2 | 4 | 64 / 2 | RoPE | 0.1 | 3e-4 | 宽度/头布局联合因素 |
| ABS | 4 | 48 / 3 | learned absolute | 0.1 | 3e-4 | 位置编码单因素 |
| MATCH | 2 | 64 / 2 | learned absolute | 0.0 | 3e-3 | 近似猫盆结构阳性控制 |

`64 / 2` 必须诚实名为联合因素：64 不能被原来的 3 heads 整除，因此它不能
单独归因于“只加宽”。MATCH 同时改变多个坐标，只验证整个 harness 能否出现
相变，不用于拆分因果。

学习绝对位置嵌入加在共享 token-interface 空间，随后分别进入左右 input
adapter；选择 learned 时 attention 内禁用 RoPE。BASE/WD0/W64H2 仍使用原 RoPE。

## 预注册门槛

只看 step 2000：

- 绑定逃逸：`free_code_acc >= 0.90` 且
  `teacher_forced_value_acc >= 0.90`；
- 组合成功：`free_chain_exact_acc >= 0.90`；
- given-4、全程轨迹与 NLL 只作机制诊断，不替代上述门槛。

## 判读规则

1. BASE 若与 v1.4-L1 不一致到足以改变逃逸判决，先审计确定性、代码与环境，
   暂停所有结构归因。
2. BASE 失败而某个单因素格成功：该因素是“足以救活本 seed”的候选；下一轮
   必须原样做双 seed、4096 fixed-valid Oracle，不能直接解冻 A/B/C。
3. 多个单因素格成功：本炉不能排序优先级；分别报告，按最小结构改动选择双
   seed 复验，不从曲线中挑最好。
4. 只有 MATCH 成功：说明模型侧组合改动足以救活，但单因素不足；下一炉从
   MATCH 反向逐项加回（depth、weight decay、RoPE、width/head）定位交互。
5. MATCH 也失败：近似仍不够。优先对账 token interface、归一化、优化器细节与
   猫盆参考模型实现，不继续盲扫超参数。
6. 无论哪格成功，本炉均为单 seed 诊断；A/B/C 继续冻结。

## 运行

Linux/macOS：

```bash
bash run_c1_v15_structural.sh
```

可选参数依次为输出目录与设备，例如：

```bash
bash run_c1_v15_structural.sh runs-c1-v1.5-structural cuda
```

v0.1.8 的 `result.json` 同时记录 `endpoint_step/endpoint_validation` 与
`best_step/best_validation`；本炉只读取前者。
