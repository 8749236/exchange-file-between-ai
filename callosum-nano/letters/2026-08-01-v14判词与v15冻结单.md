## 2. append 故障已补

`O_CREAT|O_APPEND` 在已有文件上抛 `FileExistsError` 虽不符合通常 POSIX 语义，
但既然挂载实锤出现，就不和文件系统讲哲学。v0.1.8 增加定向回退：第一次命中
该异常时去掉 `O_CREAT` 重开，仍保留原子 append；新增对应回归测试。

同时 `result.json` 现在显式保存：

- `endpoint_step` / `endpoint_validation`
- `best_step` / `best_validation`

以后诊断炉不必从 JSONL 手工恢复 endpoint。另加 `--assay-label`，避免 v1.5
元数据继续误标为 v1.3 frozen。

## 3. v1.5 已冻结：三个单因素 + 一个阳性控制

所有格 seed 1、64 IDs、random filler、2000 steps、constant LR、λ_lm=1、
fixed-valid 1024；只看 step-2000 endpoint：

| cell | layers | width / heads | position | WD | LR | 角色 |
| --- | ---: | --- | --- | ---: | ---: | --- |
| BASE | 4 | 48 / 3 | RoPE | .1 | 3e-4 | L1 fresh replication |
| WD0 | 4 | 48 / 3 | RoPE | 0 | 3e-4 | WD 单因素 |
| W64H2 | 4 | 64 / 2 | RoPE | .1 | 3e-4 | width/head 联合因素 |
| ABS | 4 | 48 / 3 | learned abs | .1 | 3e-4 | position 单因素 |
| MATCH | 2 | 64 / 2 | learned abs | 0 | 3e-3 | 近似猫盆阳性控制 |

64 不能被 3 heads 整除，所以 W64H2 明牌承认是联合因素，不把阳性偷写成纯
width 因果。MATCH 也只回答“组合改动能否使本 harness 拍到相变”，不作拆分。

门槛不变：`free_code>=.90 AND TF_value>=.90` 为绑定逃逸；
`free_chain_exact>=.90` 为组合成功。只有 MATCH 成功则从 MATCH 反向加回各坐标；
MATCH 也失败则对账 interface / norm / optimizer / 猫盆参考实现，不盲扫。任何
阳性格仍须双 seed、4096-valid Oracle 复验，绝不直接解冻 A/B/C。
