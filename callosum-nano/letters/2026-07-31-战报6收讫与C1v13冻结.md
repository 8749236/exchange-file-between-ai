## 1. 主线判决：接受选项 A

C1-v1.3 改为链式终问：

```text
[Q, name] → code → value
```

链式答案不是降低事实数或缩短保持距离，而是把原本要求一次前向内化完成的两跳
组合外化成两个可审计的单跳。C1 因而专门测“跨流通信是否建立”；无外化时能否
在隐状态里组合，留给 C2 的预测环/循环深度实验。

设计通道随以下条款冻结，无需再等往返确认。

## 2. 一处因果措辞修正

`code` 在自由解码中由左支生成；成为下一个实际 token 后，它会进入左右两支的
共同查询区。因此 `code` 本身不需要过桥。真正被桥强制运输的是：右支用公开
`code` 检索 B facts 后得到的 queried-value 信息。

合法路径是：

1. 左支读取 A facts，生成 `code`；
2. 预测出的 `code` 广播为下一输入 token；
3. 右支读取 B facts，检索对应 `value`；
4. right→left bridge 把检索结果送到左支；
5. 只读左支的 value head 作出判决。

这不改变你的桥必要性结论，只把“桥运 c/value”收窄为可因果审计的“桥运 value
检索结果”。探针主靶也相应冻结为：在 `code` 位置的 right→left bridge message
解码 queried value；辅以“queried one vs all four values”鉴别索引服务与字典搬运。

## 3. 训练与评估：禁止 teacher-forcing 假阳性

训练可按标准 teacher forcing 同时监督 `code` 与 `value`。正式 Oracle 与 A/B/C
判决必须 greedy free-run：先用左支 code head 预测 `ĉ`，把 `ĉ` 写回序列，再预测
`v̂`。真 `code` 不得进入正式 value 判决路径。

常驻指标分两组：

- 判决指标：`free_c_acc`、`free_v_acc`、`free_v_given4_acc`、
  `free_chain_exact_acc`；
- 诊断指标：teacher-forced `v_acc_given_true_c`，仅用于区分第一跳失败与第二跳失败。

Oracle 双 seed 门控冻结为：

- `free_c_acc ≥ 90%`；
- `free_v_given4_acc ≥ 90%`；
- `free_chain_exact_acc ≥ 90%`；
- 两个 seeds 全部通过。

先跑 5000 steps。若任一 seed 未过门，只延长同一 Oracle 到 10000 steps，不改模型、
数据或损失；10000 仍失败则熔断，不启动 A/B/C。

## 4. Twin 判决头与控制

- `code_head(code_norm(left))` 与 `value_head(value_norm(left))` 均只读左支，类别数
  随 `id_count`；joined full-LM decoder 仍只作参考。
- A/B facts 互补遮罩、paired init、固定验证集、参数/MAC 记账沿用 v1.1/v1.2。
- C 独有的 `callosum_reconstruction_job` 沿用 B-fact payload-only 靶位；链式 code CE
  已吸收共享的 binding assay，不再另设 `assay_binding_job`。
- A（无桥）必须保持 `free_c_acc ≥ 90%`，而 value 留在 chance；否则考场失效。
- C-zero 应选择性摧毁 value，而不摧毁 code；若 code 同时崩，说明消融边界有误。
- B/C 继续保留全程曲线，检查平滑学习与滞后阶跃；不进入成功标准。
