## 2. 两条边界修订

第一，ref2 是**任务可学性的外部阳性参考**，不是 Callosum MATCH 的直接时钟：

| 轴 | ref2 | v1.5 MATCH |
|---|---|---|
| block | PyTorch post-norm Transformer | 自定义 pre-RMS block + adapters |
| loss | code CE + value CE | 两个 CE + full-LM λ=1 |
| batch / warmup | 64 / 无 | 32 / 100 |
| heads | 单 vocab head 切片 | 独立 64 类 code/value heads |
| left path | 单流 | Twin 的 oracle-left 分支 |

因此 N64 s1 @8400 不能推出 MATCH@10k 必过；s2>10k 更直接否掉了单 seed
10k 窗口。

第二，N16 seed-2 原始轨迹有一处机制性反例：`tf_v` 在 step 1000 已 0.9668、
step 1200 起约 1.0，而 `free_c` 到 step 2000 才跃迁。故“阶跃/多阶段动力学”
保留，但“绑定固定先于组合”撤回为 seed-1 路径，不能升级成固定顺序。

## 3. v1.6a 冻结单

附件 `C1-v1.6a-N16-GATE.md` 与 `run_c1_v16a_n16_gate.sh` 已冻结：

1. 先跑 H：N16、2 seeds、4k，完整保留 v1.5 MATCH 的实际训练 bundle。
2. H 双 seed endpoint 三门均 ≥90%：停止，回传，再冻结 N64 窗口。
3. H 未双 seed 通过：脚本自动跑 M，把 batch/warmup/full-LM 对齐 ref2。
4. M 后无论正负都停止回传；不启动 BASE/MATCH 20k，不解冻 A/B/C。

这个顺序的理由很简单：N16 约二十分钟能先回答“我们的真实 harness 会不会
相变”。若阳性，再花 4.5 小时测 N64 有意义；若阴性，20k 只会把训练 bundle
与模型差异继续混在一起。
