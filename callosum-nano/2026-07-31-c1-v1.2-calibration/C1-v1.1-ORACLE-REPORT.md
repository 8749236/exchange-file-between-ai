# Callosum Nano C1-v1.1：Oracle 熔断报告

日期：2026-07-31
状态：`C1-v1.1-frozen` 实现完成；Oracle 熔断；A/B/C 未运行

## 一句话判词

管线与考卷通过了遮罩、因果性、梯度和续训 smoke，但 5000-step
`oracle-left` 只达到 12.52% accuracy，不能算“Oracle 成功”。按预注册规则，
本炉在进入桥条件前作废；当前没有关于“桥是否需要差事”的实验结论。

## 冻结考场

- 每个 episode 有 4 条 `name→code` A 事实、4 条乱序 `code→value` B 事实。
- 左支看不到 B，右支看不到 A；query 对双方可见。
- 答案头为左支专用 64 类 head，value `128..191` 映射为类别 `0..63`。
- joined decoder 只作为全序列 LM 参考，不能参与判决指标的 late fusion。
- C 条件的辅助作业只重建 B payload；固定 `B_MARK` 不进入 job mask。
- 正式验证为 seed 固定的 4096 episodes；最佳 checkpoint 按 `answer_nll`。
- 条件矩阵：Oracle、A 无桥、B rank-8 无作业、C rank-8+重建、C-zero 关桥。
- 熔断：Oracle 不成功，或 A 脱离 chance，则整炉不得解释 B/C。

## 工程审计

新增实现包括：

- C1 可续训数据流、互补视图、答案位和 payload-only job mask；
- 64 类左侧答案头与独立 256 类 job head；
- 可开关的同步双向 Callosum 与逐层消息采集；
- 每步 train answer NLL/accuracy/EMA 曲线；
- 固定验证、C-zero、参数分组记账、best/latest checkpoint；
- 非阻塞运行锁与 resume 超参数校验。

测试结果：`23 passed`。覆盖旧 C0 回归、遮罩与 marker 剔除、未来答案
因果隔离、桥 identity/开关、R→L 作业梯度、配对初始化、固定验证重复性、
数据流及训练断点逐参数一致。

## 正式 Oracle 结果

配置：seed 1，4 layers，branch width 48，3 heads，MLP ratio 4，batch 32，
5000 steps，warmup 100 + cosine decay，固定验证 4096 episodes。

| 指标 | Chance | Oracle best |
| --- | ---: | ---: |
| answer NLL | 4.1589 | **3.3028** |
| answer accuracy | 1.5625% | **12.5244%** |
| best step | — | 5000 |

曲线在约 step 3500 后平台化于 12% 左右。它显著离开 chance，说明目标、
索引和梯度并非全坏；但它远未可靠解决两跳任务，不能满足 Oracle 熔断条件。

## “模型到底学了什么”探针

在同一 best checkpoint、同一 4096 episodes 上：

| 诊断 | 结果 |
| --- | ---: |
| 真答案 top-4 recall | 37.89% |
| top-1 是本 episode 的四个 value 之一 | 49.66% |
| 四个 value 的总概率质量 | 20.68%（均匀基线 6.25%） |
| 仅允许四个真实 value 后的 accuracy | **25.07%** |
| 真答案平均/中位 rank | 10.70 / 7 |

最后一项是关键：25.07% 等同四候选四选一。模型学会了从 filler 中发现
“本题有哪些 value”，但没有学会用 query name 选择对应 value。失败点在
随机符号的内容寻址/绑定，而不是 64 类答案头或未来答案泄漏。

## Oracle-only 诊断炉

这些条件不进入 C1 判决，仅用于定位 assay：

| 诊断 | steps / valid | best NLL | best accuracy | 判读 |
| --- | ---: | ---: | ---: | --- |
| 原两跳正式 Oracle | 5000 / 4096 | 3.3028 | 12.52% | 弱阳性、平台化 |
| query 直接给 code（B 一跳） | 2000 / 512 | 3.5142 | 10.94% | 未可靠寻址 |
| A 改为 name→value（直接一跳） | 2000 / 512 | 3.0887 | 21.68% | 更易但仍未解决 |
| 直接一跳，关闭 full-LM loss | 1000 / 512 | 3.4905 | 16.21% | 与同阶段 full-LM 版 accuracy 相同 |

直接一跳在保留 full-LM 时 step 1000 也是 16.21% accuracy，且 NLL 更低
（3.3081）。因此全序列 LM 学习税不是主要瓶颈。

## 结论边界

可以说：

1. C1-v1.1 的实现与审计管线已就绪；
2. 当前茶杯模型能部分编码候选 value，但随机 key-value 寻址太难；
3. Oracle 熔断有效地阻止了一个不可判读的桥实验。

不能说：

1. 无桥 A 会失败或有桥 B/C 会成功；它们尚未运行；
2. 重建作业有用或无用；
3. Callosum 在“必须合作”任务上得到正/负结果。

## 建议的 C1-v1.2 校准顺序

保持 v1.1 结果封存，重新开放的只应是 Oracle 考场校准，不是 B/C 解释：

1. 先做 Oracle-only 小网格，降低随机 ID/value 类别数（例如 16），保留
   4 facts 与真正两跳；
2. 若仍不可靠，再去掉 37-token filler，隔离保持/干扰难度；
3. 预先设定强阳性门槛（建议 accuracy ≥90%，且至少 2 seeds），选择最小
   能跨门槛的考场后重新冻结；
4. 所有 A/B/C 使用同一新考场、同一训练预算与 paired init；
5. C2 连续低秩预测误差通道仍保持独立，不因本次 C1 Oracle 失败而改变。

“降低类别数”和“去 filler”必须标为 v1.2 assay calibration，不能回写成
v1.1 的成功结果。
