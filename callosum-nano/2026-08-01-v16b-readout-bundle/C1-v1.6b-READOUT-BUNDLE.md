# C1-v1.6b：shared-vocab-plain readout bundle（冻结）

日期：2026-08-01

## 前置判决

C1-v1.6a 的 H/M 四跑均在 N=16、step 4000 保持集合随机水平，四份日志审计
全绿。M 已对齐 ref2 的 batch=64、无 warmup、仅 code/value 两个 CE；因此不启动
N64/20k，也不解冻 A/B/C。

## HEAD-MERGE 假设的修正

ref2 先执行：

```python
full_logits = head(state)
code_logits = full_logits[:, 64:64+id_count]
loss = cross_entropy(code_logits, code_targets)
```

CE 只看切片后的 `id_count` 个 logits。它与一个独立
`Linear(width, id_count)` 的类别对手集合严格相同；共享 256 行容器不会引入
全词表 softmax 竞争。

ref2 与 Nano readout 真正同时不同的是：

- ref2 没有 code/value head 前的独立 RMSNorm；
- ref2 使用 PyTorch `Linear` 默认初始化和 bias；
- 两组有效行位于一个 256 行参数容器中。

所以本炉命名为 **readout bundle**，不把结果归因给 merge 本身。

## 单格配置

- `oracle-left` only；exact `chain-two-hop`；N=16；random filler
- 2 layers / width 64 / 2 heads / learned positions
- batch 64；lr 3e-3；warmup 1；constant LR；WD 0；clip 1
- full-LM λ=0；4000 steps；validation 1024；seeds 1,2
- `c1_head_style=shared-vocab-plain`

shared head 直接读取左支最终状态，输出 256 logits，再分别切 `[64:80]` 与
`[128:144]`。unused rows 不参与 CE、无梯度；job head 保持存在但本炉不使用。

## 预注册门与判读

每个 seed 的 step-4000 endpoint 同时要求：

- `free_code_acc >= 0.90`
- `free_v_given4_acc >= 0.90`
- `free_chain_exact_acc >= 0.90`

| 结果 | 判读 |
|---|---|
| 双 seed 通过 | readout bundle 足以恢复相变；下一炉再拆 head norm / init+bias，不能宣称 merge 定罪 |
| 任一 seed 未通过 | readout bundle 不足以救活；转向 post-LN / 输入尺度与 adapters 的模型梯子 |

不延长步数、不挑 seed、不用 best 替代 endpoint、不自动启动下一炉。
