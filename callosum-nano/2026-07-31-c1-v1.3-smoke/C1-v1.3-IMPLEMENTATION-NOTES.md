# C1-v1.3 实现说明

## 数据与因果结构

- 新增 `chain-two-hop`，context 65。
- facts `0..23`、37 filler `24..60`、Q/name `61..62` 均不移动。
- teacher-forced code/value 位于 inputs `63..64`；code/value 判决 mask 位于
  targets `62..63`。
- 正式 free-run 只读取 prefix `0..62` 预测 code，将预测 token 写回位置 63，
  再做第二次因果前向预测 value；真 code/value suffix 被切除。

## 判决头与损失

- `code_head(code_norm(left))` 与 `value_head(value_norm(left))` 均只读左支。
- 训练总损失为 full-LM CE + code CE + value CE；C 另加
  `job_lambda × callosum_reconstruction_job`。
- joined decoder 不参与 C1 判决。

## 门控与消融

- Oracle：两个 seeds 均需 free code、free value given-4、free chain-exact ≥90%。
- 默认 CLI 只跑 Oracle；chain A/B/C 必须显式 `--oracle-approved`。
- C-zero 自动记录；必须选择性摧毁 value、保留 code。
- 5000-step 首跑应预先固定 `--lr-decay-steps 10000`，才能在未过门时原样
  resume 到 10000。

## 桥探针

- 每层 right→left message 取 filler 60、query-name 62、code 63。
- train/validation 使用不同固定随机流；确定性 ridge probe 同时报
  queried-code、queried-value、all-four top-4 recall 与 exact-set accuracy。
- `--probe-episodes 0` 默认关闭；只应在 Oracle 过门后的 B/C 最优 checkpoint
  上启用。
