# C1-v1.7：direct-input 正式 A/B/C（冻结）

日期：2026-08-02

## 性质与前置证据

本炉回到 C1 主问题：当左右支的证据严格互补、答案头只读左支时，低秩桥是否
运输右支检索出的 value，以及显式桥差事是否改变学习结果。

前置 Oracle 采用 v1.6c 的 INPUT 格：Nano pre-RMS block + direct-default input，
seed 1/2 分别在约 step 600/1200 达到三项近满分。BOTH-EXT 的阴性只禁止对
block/input 作完整因果归因，不撤销 INPUT bundle 已足以使 Nano Oracle 双 seed
可解的事实。

## 冻结配置

- exact `chain-two-hop`、N16、4 facts、random filler；
- 左支遮 B、右支遮 A；code/value heads 只读左支；
- Nano pre-RMS block、direct-default input、shared-vocab-plain head；
- 2 layers、branch/interface width 64、2 heads、MLP ratio 4；
- rank-8 每层同步桥；
- batch 64、10,000 steps、fixed validation 4,096、eval interval 200；
- AdamW，lr 3e-3、warmup 1、constant LR、WD 0、clip 1；
- full-LM lambda 0、job lambda 0.1、seeds 1/2；
- B/C 的 best checkpoint 均做 4,096+4,096 episode 线性桥探针。

10k 窗口在看 A/B/C 结果前冻结。理由是先前不同实现均出现两跳分离与 4k–8k
长寿命平台；本炉不再用短窗口把重尾逃逸自动命名为永久死锁。

## 条件

| 条件 | 桥 | 重建差事 |
|---|---|---|
| A | 无 | 无 |
| B | rank 8 | 无 |
| C | rank 8 | B-fact payload-only 同位重建，lambda 0.1 |

C-zero 在 C 的 best checkpoint 上关闭全部桥，不重训。

## 熔断与判读

先只跑 A。两个 seed 的 10k endpoint 必须同时满足：

- `free_code_acc >= 0.90`；
- `free_value_acc <= 0.10`；
- `free_v_given4_acc <= 0.30`；
- `free_chain_exact_acc <= 0.10`；
- 10,000/10,000 train records、51/51 fixed eval records，日志审计全绿。

这要求 A 学会第一跳，但第二跳保持在 N16 overall chance（1/16）与 given-4
chance（1/4）附近。任一 seed 失败即整炉无效，B/C 不启动。

B/C 每格均以双 seed 10k endpoint 的 `free_code`、`free_v_given4`、
`free_chain_exact` 全部不低于 0.90 为通过。best checkpoint 仍按固定验证集上的
free-value NLL 机械选择，不按最终结论挑点。

C-zero 必须双 seed 保持 `free_code >= 0.90`，同时回落到
`free_value <= 0.10`、`free_v_given4 <= 0.30`、`free_chain <= 0.10`。

- C 过、B 不过、C-zero 过：支持“本考场中桥需要显式差事”；
- B/C 都过且 C-zero 过：桥必要，但显式重建差事不必要；
- C 过但 C-zero 不过：禁止通信机制归因；
- C 双 seed 未过：重建差事在本冻结配置下不足。

B/C 全程曲线与各层 filler/query/code 位置探针均为机制诊断，不进入成功门。

## 执行

```bash
bash run_c1_v17_formal_abc.sh runs-c1-v1.7-formal-abc cpu
```

脚本先跑测试和 autograd preflight，再执行 A 熔断；只有 A 通过才启动 B/C。
