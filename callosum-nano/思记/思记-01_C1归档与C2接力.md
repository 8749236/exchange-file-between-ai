## 1. 最初的问题

Callosum Nano 想检验一个很小、但可证伪的“左右脑”脑洞：在近似相同参数 / MAC
预算下，两个半宽、权重独立的 Transformer 流，加一条窄低秩通信桥，是否能比单个
窄 Dense Transformer 更有效地学习；以及桥在什么条件下会真正运输任务相关信息。

基本对象：

- **Narrow Dense**：单流、较窄，用作等预算主对照；
- **Twin No-Comm**：两个半宽独立流，末端合并，无中途通信；
- **Twin Callosum**：Twin 加每层低秩双向桥；
- **Wide Dense**：预算外上界参考，不参与“等预算获胜”判决。

“左右脑”“胼胝体”只是工程隐喻，不是生物学同构声明。

## 2. C0：普通语言建模比较

早期 C0 结果形成了两个不同层级的观察：

1. Twin 的早期领先主要是优化速度优势；约 1,800–2,000 步后 Narrow Dense 追平，
   不能把瞬态领先写成最终质量优势。
2. 5,000×3 seed 中，Twin 对 Narrow 的方向一致预算效率信号仍存活：Twin 三 seed
   均不差于 Narrow，参数约少 8.9%；但样本、尺度和任务太小，只能叫信号。
3. C0 中 rank-8 Callosum 相对无桥的差约 `+0.000098`（n=3），正式判 null。
   这不等于“桥永远无用”，只说明普通模板化语料没有迫使模型跨流合作。
4. Wide Dense 全胜但预算更大，只是上界参考，不能拿来支持等预算 Twin 结论。

因此 C0 没有证明“两个半模型等于一个全模型”，更不能外推到 Billion / Trillion
参数。它只给出了继续研究分解结构与优化动力学的理由。

## 3. C1：把跨流通信变成唯一合法路径

C1 构造 episode 内随机符号绑定：

- 左支只见 A facts：`name -> code`；
- 右支只见 B facts：`code -> value`；
- 正式答案头只读左支；
- 查询要求完成 `name -> code -> value` 两跳。

结构熔断包括 Oracle 阳性、A 无桥应保持第二跳随机、未来真值不可见、桥清零、固定
验证集、paired seed、完整轨迹与 endpoint 判读。Oracle 不过时禁止解释桥实验。

### 3.1 Oracle 与结构诊断教会了什么

多轮 Oracle / 架构梯子揭示了一个先于通信的问题：答案监督在 episode 内随机绑定上
常进入“存值丢钥”的稳定平台。模型知道有哪些 value，却没有保留 key-value 对应。
这不是单纯“桥不工作”，因为全可见单支 Oracle 也能出现同样表型。

降低到 N16、direct-default input、Nano pre-RMS block 后，Oracle 双 seed 可解，
考场才获得继续考试桥的资格。中间 v1.3–v1.6 的阴性和梯子用于校准仪器，不应被
压缩成某一组件的单因果定律。

### 3.2 C1-v1.7：值袋子，没有绑定

正式 A/B/C 结果：

- A（无桥结构熔断）通过；
- B（桥、无差事）双 seed 失败；
- C（桥 + B-fact payload 重建差事）双 seed 失败；
- C-zero 通过：关桥后 value 路径选择性崩回随机。

C 并非没完成重建：job CE 已很低，answer top-4 recall 约 1，四个 episode value 的
概率质量约 .97，但 given-4 仍约 1/4。桥确实搬来了 value 集合，却没有搬来
`code -> value` 的关系。机制名：**值袋子，无绑定（bag of values without
binding）**。

由此得到一条比“通信需要差事”更精确的经验命题：

> 通信差事必须瞄准任务真正缺失的关系；奖励 payload 搬运会得到 payload，
> 不会自动得到 key-value binding。

## 4. C1-D：地址去，值回

第一版“让右支预测 value 类”的 query job 仍可从 value bag 中四选一，被本地校准
否决，没有进入正式包。冻结版显式加入 assay-specific 四槽 pointer/retrieval：

1. 左支位置 63 持有 query code，右支同位为 MASK；
2. 第一层左→右 rank-8 桥发送地址；
3. 右支在随机排列的四个 B-code 槽中选择匹配槽，并读取同槽 value state；
4. 最后一层右→左 rank-8 桥把 value 送给左支答案头。

D0 与 D 参数、初始化和结构完全相同；唯一差异是 D 将四槽地址 CE（lambda 1.0）
计入 loss，D0 不计。

### 4.1 正式结果（v0.1.15，10k，4096 fixed-valid，双 seed）

| cell | seed 1 endpoint | seed 2 endpoint | 判读 |
|---|---:|---:|---|
| D：地址作业 | code/qjob/chain = 1.000 | code/qjob/chain = 1.000 | 双 seed 通过 |
| D0：无地址作业 | chain .255，qjob .256 | chain .984，qjob .989 | 1/2，seed-dependent |

D 两 seed 都在约 400–800 步阶跃到近满分，随后保持至 10k。D0 seed 1 全程困在
四选一；seed 2 从约 step 3,800 开始缓慢爬升，到 10k 才接近学会。

方向清零门双 seed 全部通过：

- 关左→右：qjob 回到 `.252/.258`，given-4 回到 `.252/.259`；
- 关右→左：qjob 保持 `1.000/1.000`，左答案回到 `.062/.059`；
- 双向全关：qjob 回到 `.252/.258`，左答案回到 `.062/.059`。

线性探针在成功模型最后一层、位置 63 的右→左消息中解码 queried value：

- D：`.928 / 1.000`；
- D0：失败 seed `.212`，成功 seed `.992`；
- N16 随机地板约 `.0625`。

所以当前最强、同时保持边界的结论是：

> 在显式提供 query/retrieval 归纳偏置的 C1 assay 中，rank-8 低秩双向桥能够承载
> “地址去、值回”的稳定协议；直接监督缺失的地址关系，使该协议在 10k 窗口内从
> seed-dependent 变成双 seed 可靠。

这不是“plain Transformer 会自发发明寻址”的证明。pointer 模块已经提供了结构
偏置；实验判定的是低秩桥能否承载并学稳两腿协议，以及地址作业的可靠性贡献。

## 5. 证据纪律与事故记录

本项目保留以下硬规则：

- 校准用于修考卷，不冒充正式证据；
- 事先冻结条件、窗口、门槛与 best-checkpoint 规则；
- paired seeds，同一环境内比较；endpoint 与 best 分开；
- fixed validation、完整逐步曲线、原始 checkpoint/probe、SHA256；
- smoke 主动找捷径，并检查遮罩、因果性、梯度方向和清零必要性；
- 熔断失败即停炉，不在现场改源码继续跑；
- “没有观察到”不升级成“永远不存在”，Nano 结论不外推到大模型。

v0.1.14 曾因 probe collector guard 只允许 B/C、未允许 D0/D，在首格训练 10k 后
崩溃。猫盆正确熔断并保全现场。v0.1.15 只修 guard、加入真实 probe 回归测试，
49/49 tests 后从全新目录重开；正式炉通过。这个事故应保留在错题本：调用路径允许
新条件，不代表下游旧 guard 自动同步。

本地校准使用 torch 2.13.0+cpu；猫盆正式炉使用 torch 2.8.0+cu128 的 CPU 路径并
固定 OMP/MKL=2。seed 不保证跨 PyTorch / 线程归约实现位级同轨；正式比较只依赖
猫盆同环境内的 paired D0/D。

## 6. 当前知识边界

已经有正式证据支持：

- 桥能产生因果贡献，不只是参数摆设；
- 搬运 value 集合与学习 binding 是两件事；
- 左→右地址腿、右→左 value 腿可被独立清零验证；
- 针对地址关系的作业显著提升双向协议的训练可靠性。

仍未证明：

- Twin 在通用语言建模上的最终质量优于等预算 Dense；
- 结论能随参数规模放大；
- 普通 Transformer 会自发形成同样协议；
- rank 8 是最优或最小桥宽；
- 生物脑结构与该模型存在超出隐喻的同构；
- 预测编码闭环对通用模型有效。

## 7. 下一步：C2（尚未开炉）

C1 到此归档。C2 保留此前冻结的独立语义：**误差反馈通道的最小连续低秩带宽**，
不要把 C1-D 改名成 C2。

已达成的 C2 前置约束：

- 证据必须对读取方不可见，否则误差反馈可能冗余并收学习税；
- 通道使用连续低秩向量；主 sweep 为 rank `1/2/4/8`；
- scalar 是预注册 null control；
- 不在主实验混入 sign/STE、VQ 或其他量化风险变量；
- `k` 是连续通道维数，不是物理 bit 数；
- 猫盆战报 5 的“k=2 足够”只属于其特定残差分布，不外推为普遍压缩律；
- 若未来必须离散化，课程式码本、软量化退火、读者侧量化都只是未验证候选，放在
  C2 之后。

### C2 开炉前的下一动作

先从战报 4/5 与双方旧信恢复一份**自足的 C2 冻结单**，明确：任务生成、证据遮罩、
误差定义、通道注入时序、训练目标、scalar control、rank 参数记账、Oracle / zero
controls、双 seed 与预注册判读。然后实现 smoke；smoke 通过前不跑正式 sweep。

不要直接从 C1-D 代码“顺手改一个误差向量”就开炉：C1 的答案寻址与 C2 的误差反馈
是两个独立假设，混用会失去可判读性。
